[긴급 분석] Xen Orchestra 이중 제로데이 사태와 관리자 권한 우회 원리 (VSA-2026-062)

Xen Orchestra에서 미인증 공격자가 관리자 세션을 탈취하고 호스트 권한까지 장악할 수 있는 이중 제로데이(VSA-2026-062·063)가 공개됐다. 웹소켓 RPC 인증 우회 경로와 RCE 체이닝, 즉시 적용할 완화책을 정리했다.

김도현 #XenOrchestra#VSA-2026-062#가상화#제로데이

엔터프라이즈 가상화 인프라(XCP-ng, Citrix Hypervisor)의 핵심 오케스트레이션 솔루션인 Xen Orchestra에서 미인증 원격 공격자가 관리자 세션을 탈취하고 호스트 시스템 권한까지 장악할 수 있는 이중 제로데이 취약점(VSA-2026-062, VSA-2026-063)이 공개되었습니다. 본 리포트에서는 웹소켓 RPC 프로토콜의 인증 우회 원리와 원격 코드 실행(RCE) 체이닝 과정을 상세히 분석합니다.

1. 위협 개요: 하이퍼바이저 관리 계층 침해 위협

Xen Orchestra는 수천 대의 가상 머신(VM), 스토리지 풀, 가상 네트워크를 웹 인터페이스를 통해 일괄 통제하는 중앙 관제 시스템입니다. 본 시스템이 침해될 경우 단일 VM 탈취에 그치지 않고, 동일 호스트에서 구동 중인 모든 테넌트 VM의 메모리 덤프, 스냅샷 탈취, 하이퍼바이저 호스트 시스템의 root 권한 장악으로 직결됩니다.

공격자는 외부 포트(기본 80/443)에 접근 가능한 네트워크 위치에서 사전 인증이나 자격 증명 없이 악성 웹소켓 프레임을 전송해 관리자 권한을 완전히 획득할 수 있습니다.

2. 취약점 근본 원인: 빈 JSON 객체 파싱과 토큰 검증 무력화 (VSA-2026-062)

Xen Orchestra의 백엔드는 클라이언트 세션을 검증할 때 HTTP 쿠키에 포함된 JSON Web Token(JWT) 또는 인증 토큰을 파싱합니다. 취약점의 핵심은 인증 토큰 파싱 로직에서 타입 검증 부재와 객체 참조 오류에 기인합니다:

// 취약한 인증 토큰 검증 로직 간소화
const cookie = parseCookie(req.headers.cookie);
if (cookie.token) {
  const session = getSession(cookie.token);
  // cookie.token이 빈 객체 '{}'일 경우 falsy 검사를 통과하며 기본 관리자 세션 반환
}

공격자가 요청 헤더의 세션 쿠키 값으로 j:{}(빈 JSON 객체)를 전달할 경우, 토큰 유효성 검사 루틴은 이를 문자열이 아닌 유효한 객체로 인식합니다. 내부 세션 테이블 조회 함수가 빈 객체 키에 대해 예외를 발생시키지 않고 메모리에 캐싱된 기본 관리자 컨텍스트(Admin Context)를 반환하는 결함이 발생하며, 결과적으로 미인증 사용자가 즉시 최고 관리자 권한을 부여받게 됩니다.

3. 공격 체이닝: 웹소켓 RPC 인증 우회와 하이퍼바이저 RCE (VSA-2026-063)

관리자 세션을 탈취한 공격자는 Xen Orchestra의 실시간 웹소켓 RPC 엔드포인트(/api/)로 공격 표면을 확장합니다:

  1. 웹소켓 핸드셰이크 권한 우회: 1단계에서 획득한 무력화된 관리자 쿠키를 사용해 웹소켓 연결을 수립합니다. 서버는 세션을 최고 권한 관리자로 영구 바인딩합니다.
  2. 특권 RPC 프로시저 호출: Xen Orchestra 내부의 플러그인 관리 API 및 원격 진단 명령어 인터페이스(vm.execute, host.execShell)를 호출합니다.
  3. 하이퍼바이저 호스트 명령 실행: 관리 콘솔이 설치된 리눅스 호스트의 root 권한으로 임의 쉘 스크립트가 실행되며, 물리 하이퍼바이저와 연결된 스토리지 네트워크 전체가 공격자 수중에 떨어집니다.

4. 패치 분석 및 인프라 방어 가이드

1. 긴급 보안 패치 즉시 적용:

Xen Orchestra 소스 빌드(XO-from-the-source) 및 공식 어플라이언스(XOA) 사용자는 배포된 최신 보안 릴리스로 즉시 업데이트하십시오. 최신 패치는 토큰 파싱 시 엄격한 스키마 검증(Strict String Type Check)을 강제하고 빈 객체 유입 시 즉시 세션을 파기하도록 수정되었습니다.

2. 관리 인터페이스 네트워크 분리 (임시 방어):

패치 적용 전까지 Xen Orchestra 웹 포트(80, 443)의 공용 인터넷 노출을 즉시 차단하고, 신뢰된 관리자 전용 내부 VPN 또는 전용 서브넷에서만 접근 가능하도록 방화벽 ACL을 재설정하십시오.
